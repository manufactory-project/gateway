# `gatewayd` Threat Model (v0.1)

`gatewayd` treats every connected guest as hostile. A guest may be steered by prompt injection, untrusted repository content, or malicious code it executes, up to and including root inside the guest. Containment does not depend on guest cooperation, agent discipline, or in-guest sandboxing; the locked plain-Go wire suite and `gatewayd-probe` are the living verification inventory.

## Hardening Goals

1. **Protect the LAN, host, and other guests — total across every protocol and address family.**
   A guest cannot reach the host, management interfaces, LAN peers, cloud metadata endpoints, loopback, link-local, non-global IPv6, or other sandbox guests. Enforcement spans Linux `nftables` (per-link conntrack zones, IPv4-only sandbox links, `fib daddr type local` guards, default-`drop`), kernel sysctls (`ip_forward=0`, IPv6 forwarding off, `rp_filter=2`, ARP suppression), fake-IP DNS (zero upstream query forwarding), dial-by-name, and connect-time `Dialer.Control` checks (`Unmap()` before prefix matching; private-IP pins scoped strictly to `(principal, host, port, matchedRule)` or static `records`).

2. **Keep declared secrets out of the guest.**
   Declared API keys and credentials stay on the host behind a `file`-only secret provider. Guests hold only inert `mf_ph_*` placeholders. `gatewayd` substitutes a secret only into the exact `(host, port, header, scheme)` declared by a Binding, unconditionally strips `Proxy-Authorization` and any remaining `mf_ph_*` (including decoded Basic Auth) from every outbound request, forces `Accept-Encoding: identity` on bound hosts (failing closed `502` on compressed responses), and scrubs literal, URL-encoded, and JSON-escaped echoes of bound secrets from response headers, bodies, and trailers back to their placeholders. This goal carries the security weight because Goal 3 is open by design.

3. **Data leaving is bounded and attributable, not prevented.**
   Every DNS query and HTTP request is evaluated against an explicit default-deny allowlist per link principal and written to a fail-closed structured JSONL audit log (paths only or query strings redacted; never header values). Active flows are tracked per request/stream and torn down immediately (`cancel()` + `conn.Close()`) on `gwctl revoke`, TTL expiry, or `SIGHUP` rule/grant removal.

## Accepted Residuals (By Design)

- **Guest-held subscription OAuth tokens and arbitrary vendor credentials:** Allowlisted LLM vendor APIs accept any credential the guest presents, so data can leave to an account the operator does not own. Subscription OAuth tokens (`claude`, `agy`, `codex`) live inside the guest by design so workers can use personal subscriptions under unmodified vendor CLIs.
- **Exfiltration within a credential's scope and through allowed destinations:** A placeholder prevents the guest from reading the raw secret, but an agent can still exfiltrate any data the credential legitimately reaches (for example, pushing to a repository the token can write) or encode data into paths, query strings, headers, or bodies sent to an allowlisted host. Scoping credentials at their source and writing exact-host, method, and path rules bound the channel.
- **Cross-host secret reflection and compressed responses on bound hosts:** A secret stored upstream on bound host A and later served back from unbound host B is not scrubbed. On a bound host, an upstream API that ignores `Accept-Encoding: identity` and insists on returning a compressed `Content-Encoding` fails closed (`502`).
- **DNS label leakage under wildcard rules:** Because `gatewayd` resolves allowlisted hostnames upstream when dialing, wildcard allow rules (`*.example.com`) let a guest leak guest-chosen labels to that zone's authoritative DNS servers via `gatewayd`'s upstream resolver. Prefer exact-host rules wherever possible (mandatory for multi-product subscription vendor domains).
- **Globally routed host and LAN addresses:** `gatewayd`'s connect-time guard denies loopback, link-local, RFC 1918, CGNAT, and IANA special-purpose ranges, and restricts IPv6 to global unicast `2000::/3` minus special ranges. However, if the host or a LAN peer holds an ordinary globally routed unicast IPv4 or IPv6 address, `gatewayd` cannot distinguish it from any other internet destination without deriving a dynamic deny list from host interfaces, so an allowlisted domain resolving to that address is reachable.
- **CA private key at rest:** The operator-supplied `ca_key` is the trust anchor every guest accepts for any hostname. It sits behind the host/gateway-container filesystem boundary; anyone holding `ca_key` plus a network position between a guest and `gatewayd` can impersonate any TLS server to guests. `gatewayd` always verifies upstream TLS certificates against system roots, so `ca_key` alone confers no upstream interception. Because the CA carries no name constraints, guests cannot scope what they trust `gatewayd` to intercept. Rotation requires generating a new CA (`gwctl ca init`), updating guest trust stores, and restarting `gatewayd`.
